**CI-01 — Mutable actions execute with access to build credentials or repository writes**  
**Severity: high · Confidence: high**

Locations and exact snippets:

[.github/workflows/build.yml:139](/Users/timmy/work/gam-review/audit/src/.github/workflows/build.yml:139):

```yaml
        uses: jay0lee/python-openssl-latest@v1
```

[.github/workflows/upgrade_deps.yml:26](/Users/timmy/work/gam-review/audit/src/.github/workflows/upgrade_deps.yml:26):

```yaml
        uses: astral-sh/setup-uv@v3
        with:
          version: "latest"
```

The Python/OpenSSL action can change without a GAM commit. Google authentication runs before it; signing credentials and `GAM_GHA_*` OAuth credentials are used later on the same runner. A compromised action could alter the interpreter, persist into later steps, steal credentials, or contaminate signed and attested binaries.

The dependency updater grants `contents: write` and `pull-requests: write`, and checkout retains credentials by default. Its mutable setup action therefore runs with repository-write capability. The legitimate updater creates a PR, but compromised action code could attempt other writes permitted by repository rules.

Three additional mutable references occur in `codeql-analysis.yml:44,55,69`:

```yaml
      uses: github/codeql-action/init@v3
      uses: github/codeql-action/autobuild@v3
      uses: github/codeql-action/analyze@v3
```

These have a narrower visible impact: CodeQL permissions include `security-events: write`.

**History:** `efa65de7afa7`, attributed to Jay Lee on 2026-09-27, replaced inline Python/OpenSSL build steps with `python-openssl-latest@v1`. `d12289c4f4aa`, also attributed to Jay Lee, introduced `setup-uv@v3` on 2026-06-27.

**Confirm:** Obtain independently authenticated action revisions and their transitive downloads; inspect repository rules and effective token permissions. Pin actions and tool distributions to reviewed immutable inputs.

**CI-02 — Custom cryptography wheels are installed from an unversioned release without independent verification**  
**Severity: high · Confidence: high**

[.github/workflows/build.yml:283](/Users/timmy/work/gam-review/audit/src/.github/workflows/build.yml:283):

```bash
            gh release download --repo "jay0lee/cryptography-wheels" --pattern "*[^t]-win_arm64.whl" --clobber
            "$PYTHON" -m pip install cryptography-*.whl
```

A corresponding macOS conditional at lines 285–288 downloads:

```bash
            gh release download --repo "jay0lee/cryptography-wheels" --pattern "*[^t]-macosx_15_0_x86_64.whl" --clobber
            "$PYTHON" -m pip install cryptography-*.whl
```

Neither download specifies a release tag, asset digest, signature, or attestation verification. This trusts replaceable executable content from a separate personal repository. Compromise could affect both CI credentials and distributed GAM binaries.

`pyproject.toml:13` pins `cryptography==50.0.2`, but a matching package version does not authenticate wheel contents. Subsequent installation also does not establish that the earlier wheel was trustworthy.

The Windows ARM64 path is explicitly configured. The macOS condition compares `RUNNER_ARCH` with `x86_64`, whereas this workflow elsewhere handles GitHub’s `X64` spelling; its actual execution needs confirmation.

**History:** Windows custom-wheel downloads appeared in `6702e4db307d` on 2026-02-13; macOS support was added in `e4af5e612615` on 2026-06-27. Both are attributed to Jay Lee. `635f563eb9cd` later changed filename matching without adding verification.

**Confirm:** Inspect wheel production and provenance, compare exact asset hashes against authenticated build evidence, and establish which wheels reached shipped packages.

**CI-04 — Scheduled CA updater accepts downloaded trust anchors and attempts direct commits**  
**Severity: high · Confidence: high**

[.github/workflows/get-cacerts.yml:38](/Users/timmy/work/gam-review/audit/src/.github/workflows/get-cacerts.yml:38):

```bash
            curl "$url" > "$tmp_cert"
```

[.github/workflows/get-cacerts.yml:54](/Users/timmy/work/gam-review/audit/src/.github/workflows/get-cacerts.yml:54):

```bash
            cat "$tmp_cert" >> "$OUTPUT_FILE"
```

[.github/workflows/get-cacerts.yml:71](/Users/timmy/work/gam-review/audit/src/.github/workflows/get-cacerts.yml:71):

```bash
          curl -s https://pki.goog/roots.pem >> "$OUTPUT_FILE"
```

[.github/workflows/get-cacerts.yml:88](/Users/timmy/work/gam-review/audit/src/.github/workflows/get-cacerts.yml:88):

```bash
          git diff --quiet && git diff --staged --quiet || git commit -am '[ci skip] Updated cacerts.pem'
```

The following step pushes using `secrets.GITHUB_TOKEN`.

The workflow computes fingerprints and file hashes, but only records or compares them; it never checks downloaded certificates against an approved fingerprint set or independently authenticated manifest. The hash comparison allows changed content to proceed. A compromised download origin could consequently introduce trust anchors into GAM without a review step.

The downloads also omit `--fail`, so HTTP error bodies can be accepted as successful downloads. The Google bundle is appended without certificate parsing or validation.

Direct pushing is **conditional**: this workflow declares no `permissions`, so effective write access depends on inherited settings and branch rules. The files establish the attempted direct-update path, not that GitHub currently permits it.

**History:** `cbfae9226a04` and `094616e482b5`, attributed to Jay Lee on 2026-03-03, introduced and corrected the combined Let’s Encrypt/Google bundle generation. Direct CA auto-commit behavior predates those changes.

**Confirm:** Inspect effective workflow permissions, branch protection and successful update runs; compare committed CA fingerprints with independently approved roots. Require review of trust-store changes and reject malformed responses.

**Overall verdict:** The reviewed CI contains significant opportunities for upstream compromise to reach credentials and signed distributions. The available static evidence does not establish an actual compromise.

**Covered:** All 15 files under `.github`: seven workflows, three action-support files, stale configuration and four issue-template files. I checked triggers, expressions, permissions, secret handling, downloads, artifact/release flow, scheduled writes, and relevant precomputed history. I additionally read `pyproject.toml`, packaging definitions and targeted authentication functions to resolve CI questions.

**Not covered:** External action implementations, downloaded wheels/installers, live GitHub settings or logs, Google federation/IAM policy, PyPI publisher configuration, upstream SHA authenticity, dependency vulnerability databases, or a general audit of GAM application code. No repository code was executed or imported; no files were modified and no network calls were made.

**Cleared**

- **Fork-PR promotion:** No `pull_request_target` workflow or privileged consumer of PR-produced artifacts was found. Release artifacts come from the same workflow run; publishing requires the build matrix to succeed.
- **Release publishing:** GitHub publishing creates **draft** releases and excludes PR/scheduled events. PyPI uses OIDC rather than a visible long-lived API token; external environment/publisher restrictions remain unverified.
- **Retry workflow:** Its privileged `workflow_run` job only reruns a quoted numeric run ID through `gh`; it does not check out PR code or consume artifacts.
- **OAuth helper:** `decrypt.sh` writes the supplied OAuth JSON locally and prints size/type/validation results, not its contents. Configuration is under runner temp; tar/zip exclusions also name `oauth2.txt`.
- **OAuth diagnostic commands:** `oauth info` prints the client secret only with `showsecret`, which CI does not request. `show tokens` concerns Directory authorization records rather than OAuth bearer-token export.
- **Scheduled repository updates:** The legitimate dependency updater opens a PR; no auto-merge appears. `pushwiki` is push/manual-triggered, copies Markdown into the wiki repository and does not modify main.
- **Injection and runners:** No direct interpolation of attacker-controlled event text into `run:` scripts was found. No explicit `self-hosted` runner label appears.
- **Signing/attestation plumbing:** Certificate thumbprints, Apple entitlements and attestation steps have coherent build/signing purposes. They do not authenticate the upstream inputs identified in the findings.
